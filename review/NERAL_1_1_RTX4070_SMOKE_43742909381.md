## Root-cause evidence

1. The existing deterministic prefilter generated valid complete independent
   source certificates for BOTH Z3 inputs, but model-chosen strategies were
   PYTHON_SANDBOX three times each, so the exact Z3 verifier was never invoked.
   A certified input does not currently force the model to select Z3.
2. The narrow independent Python grammar cannot certify arbitrary truth/liar,
   room-assignment, and these multistep arithmetic texts. Re-executing an
   unchanged program twice cannot repair this missing application-side
   verification capability. The three identical Python code proposals
   in the new graph and second arithmetic case are evidence of wasted retries.
3. In the truth/liar case all three Python results disagree with the reference
   (3 / 1 / 1 vs 0). A successful Docker exit must NOT be promoted.
4. The synthetic case intended to exercise correction did not do so: it passed
   on its first call. The actual bounded correction loop was exercised by six
   other cases but generally failed to promote.
5. The negative case retained the byte-identical unverified Qwen fallback.
   Qwen nevertheless suggested 360 under one partial interpretation of
   the ambiguous rule. The verified flag stayed false. Thus preserving
   the fallback is not a universal guarantee of safe/correct user-facing text.
6. Three raw Qwen fallbacks ended at done_reason=length (2048 tokens), namely
   the graph, code and truth/liar cases. Their final replies were explicit
   unverified refusals rather than partial model answers.
7. Real Ollama /api/ps recorded GPU-resident QLoRA for seven tool-routed cases
   and GPU-resident Qwen for the DIRECT and fallback requests, so this is a
   genuine RTX4070 hardware observation rather than CPU-mock evidence.

## Recommended next isolated engineering step (NOT yet implemented)

- Use the independent full-source certificate as a deterministic hard routing
  constraint for Z3-eligible tasks; keep Z3 promotion gated by PR542 exact
  equivalence and the original PR537 guard.
- Detect unsupported independent Python grammars **before** spending repair
  turns on execution-only results. Fall back immediately when verification
  could never succeed for that source.
- Introduce independent full-source validation for clearly restricted
  arithmetic/combination/logic grammars. Do not treat arbitrary generated
  Python assertions as proof of original natural-language conditions.
- Improve diagnostic grading of explanatory final answers symmetrically for
  Qwen and NERAL, but never change sealed historical Blind100 data.
- Add a synthetic case where the first script fails and the second verified
  repair succeeds, to directly test the intended repair mechanism.
- No automatic merge, no retraining, no new 100-task benchmark.
