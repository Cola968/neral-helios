## Code-level improvements committed to isolated branch

1. Added `frontier350/resume_integrity350.py`: pure structural validator for a fully trained native AdamW checkpoint. Requires nonempty moment state; exact coverage of all optimizer parameter-group IDs; for both Adam moments consistent shape and dtype; matching optimizer and checkpoint step; complete RNG/sampler fields, pinned tokenizer identity, weights and valid token counters. Validation returns no training permission. Seven synthetic regression tests in `test_phoenix_resume_integrity.py` cover positive and negative paths. This is structural checking, not an independent tensor-finitedness, dataset-lineage or GPU-safety guarantee.
2. `frontier350/nextgen_v1/train_full_with_journal.py` invokes this contract on CPU **before the native trainer's model or optimizer GPU initialization**, retaining existing full SHA, disk budget and journal checks. Only this guarded entrypoint is now protected; no assertion that all native entrypoints are safe.
3. `checkpoint_journal.py` rejects missing/empty AdamW moment dictionaries **before writing a new generation**, avoiding a false complete-recovery receipt. Its initial SHA-only archive is now classified `pinned_initial_structure_unverified`; the SHA digest alone never certifies optimizer completeness. A nonempty newly committed optimizer does not, by itself, establish fully correct contents; the complete guarded trainer's source validation remains necessary. The journal's receipt classification is bookkeeping, not external audit certification. Two journal regression tests include no-writes and initial classification.
4. A second [actual SHA-gated CPU-only negative test #35345880926](https://github.com/Cola968/neral-helios/actions/runs/35345880926) passed: `require_full_adam_resume` refused the real model-only checkpoint with reason `native_optimizer_moment_state_empty`. This is an expected refusal, not a successful resume, and used no GPU, optimizer or model writes.
5. [CI after the final code changes #35346114029](https://github.com/Cola968/neral-helios/actions/runs/35346114029): 177 Phoenix, 40 SFT, 7 storage and 10 checkpoint-journal tests = **234 synthetic/code tests passed**. [Separate Python syntax run #35346113862](https://github.com/Cola968/neral-helios/actions/runs/35346113862) succeeded. These do not demonstrate model intelligence, BF16/FP32 A/B benefit or running full native training.

## Important remaining bypass — open issue #119

The direct `frontier350/train350_compiled.py` and legacy `frontier350/train350.py` still instantiate CUDA models before checking loaded checkpoint optimizer completeness, and their `opt.load_state_dict` paths do not call the new integrity contract. **Do not run those direct resume paths** on this archived checkpoint. An issue tracks source hardening and a separate, explicit warm-start design: [#119 — block direct native resume from incomplete AdamW checkpoints](https://github.com/Cola968/neral-helios/issues/119). It is deliberately open; the direct paths were not executed or declared fixed.

## Stop/go

Keep exact full pretraining resume **closed** on this original checkpoint. Instruction SFT and large-scale pretraining also remain closed pending provenance/licensing/privacy/content review, independent frozen bilingual holdout, hash-bound permission, actual safe GPU capacity and A/B free-answer correctness.
