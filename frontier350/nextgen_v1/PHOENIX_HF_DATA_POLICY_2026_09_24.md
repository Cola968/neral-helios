# Phoenix 350M — Hugging Face source audit (24 September 2026)

**Status:** policy/provenance work only. No new dataset rows were downloaded into Phoenix, no source was newly approved for training, no Hugging Face Job was started, and no weights changed.

## Decisions from the live Hub inspection

The connected Hugging Face Hub metadata was re-checked on 24 September 2026. The repository-wide executable policy in `hf_source_policy50.py` remains authoritative; this note adds a Phoenix-specific interpretation.

### Foundation families

- **HuggingFaceFW/fineweb** — Hub metadata: ODC-By; English Common-Crawl-derived web data. Existing source family remains allowed.
- **HuggingFaceFW/fineweb-edu** — Hub metadata: ODC-By; educational web text. The publisher describes model-assisted *filtering* labels, but the retained training rows are web text rather than generated answers. Existing source family remains allowed.
- **HuggingFaceFW/fineweb-2** — Hub metadata: ODC-By; multilingual web corpus including German. Existing German source family remains allowed.
- **HuggingFaceTB/finemath** — Hub metadata: ODC-By; 34B/54B-token mathematical educational web variants with model-assisted quality filtering. It remains **blocked for Phoenix weight-changing training** until the candidate-admission audit, benchmark-contamination screening, immutable revision/file hashes and an explicit source-policy change all exist.
- **HuggingFaceTB/stack-edu** — the inspected Hub metadata did not surface a top-level license tag. Because the corpus derives from large code collections, keep it blocked until file/source-level licensing is resolved.

### Human SFT

- **OpenAssistant/oasst2** — Apache-2.0; DE/EN are present; source contains human and synthetic records. Phoenix may only stage the already-defined reviewed, non-deleted, `synthetic == false`, no-`model_name` human rows. OASST2 is the preferred human SFT family, but a concrete Phoenix pack still requires independent privacy/content/license review and benchmark screening.
- **OpenAssistant/oasst1** — Apache-2.0; human crowdsourced DE/EN conversations. Keep for reproduction/legacy use. Do not deliberately stack it on OASST2 by default because the releases overlap conceptually and can duplicate conversation families.

### Research references that are NOT current Neral training sources

- **HuggingFaceTB/smol-smoltalk** — Apache-2.0 but explicitly synthetic. Useful evidence about post-training scale for small models, not an admitted Phoenix corpus.
- **HuggingFaceTB/smoltalk** — synthetic; the inspected metadata did not surface a license value. Blocked.
- **HuggingFaceH4/ultrachat_200k** — MIT, but the dataset card states the original dialogues were generated by ChatGPT. Blocked by the current own-data policy.
- **HuggingFaceH4/ultrafeedback_binarized** — MIT; model completions scored by GPT-4. Research reference only; do not treat as an automatically acceptable DPO source.
- **allenai/tulu-3-sft-mixture** — collection metadata says ODC-By, while the card explicitly notes that component licenses differ and some portions are non-commercial; it also mixes human and machine-generated sources. Do not import wholesale.
- **HuggingFaceTB/smollm-corpus** — ODC-By collection with large synthetic components such as Cosmopedia. Blocked by the current own-data policy.

## Reserved public evaluation lane

The following IDs stay permanently out of every training builder: `openai/gsm8k`, `google-research-datasets/mbpp`, `deepmind/code_contests`, `google/IFEval`, `truthfulqa/truthful_qa`, `google/boolq`, and `allenai/ai2_arc`.

The live Hub inspection reconfirmed IFEval as Apache-2.0, TruthfulQA as Apache-2.0, BoolQ as CC-BY-SA-3.0 and ARC as CC-BY-SA-4.0. Their licenses do **not** make them training data; their project role is evaluation holdout.

## Important correction to the 350M plan

The production 350M builder currently declares a proposed 52% FineWeb-Edu / 20% FineWeb / 13% FineWeb-2 DE / 15% FineMath recipe. FineMath is still blocked by the executable source policy. Therefore the recipe is **proposed, not currently authorized**.

As of this audit, the 350M builders now fail closed against `hf_source_policy50.py` before any Hugging Face streaming or shard creation. A source lock proves identity, not permission. Do not silently renormalize the other 85% and do not bypass the gate. Either FineMath passes its admission process and receives an explicit policy change, or a separately reviewed replacement recipe must be committed.

## SFT recommendation under the current policy

For the first real chat diagnostic, prefer a small **OASST2 human-only DE/EN pack** with response-only loss and explicit EOS. Use external synthetic SFT corpora only as research references unless the project deliberately changes its data-origin policy after a separate review.

This keeps the fast-lane experiment aligned with the user's own-model goal: no foreign weights and, under the current policy, no external-model-generated training rows.
