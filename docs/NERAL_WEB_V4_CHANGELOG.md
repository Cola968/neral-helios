# NERAL Web V4 – Nov 21, 2026

**Exact base:** `3d96247e391c072903c44ea41ebf22eeb7e8e5f6` (V3.10 `main`). No training/adapters changed.

- V3.10's HTTPS reader **already** fetched up to three pages concurrently in a 6-worker thread pool. V4 adds a distinct `ThreadPoolExecutor(max_workers=4)` to search **both compared subjects concurrently**, with a 5.5-second aggregate fast-path deadline. Each page remains constrained by public-IP DNS pinning, TLS verification, redirect validation, 2.5-second connect and 4-second overall URL deadline; malformed or missing read-page evidence fails closed. Data is extracted from `<main>`/`<article>` when present, with a 4,600-character excerpt budget.
- The V4 fast path generates a final comparison directly from independently parsed, literal HTTPS page facts. The old optional slow 9B model presentation step is bypassed **only** after both facts are proven. No benchmark answer, search snippet, model guess or old note entry is used as a fact. Other tasks retain the existing V3.10 tool behavior.
- Default browser platform is desktop. An explicitly specified iOS question cannot accept desktop-only Gecko/Blink evidence, and an iOS-only WebKit quote cannot establish a desktop engine. An unqualified desktop answer includes a caution that iOS may differ. Tor Browser iOS is not represented as an actual Tor Browser release.
- Old verified-note read-path unchanged. Explicit `web_query` bypasses exact-note lookup and rereads current pages. No holdout access or training in the implementation.
- **Validation is gated, not asserted in advance.** Hosted Windows/Ubuntu tests, then owner `W39-GAMINGPC-Neral` one-time stage with 20 new, independently worded browser-engine web questions. Normal production search throttling remains active; each query is spaced by 24 seconds to avoid a rapid-fire load test. Per-answer API latency excludes that external pacing. Required outcome: mean <6.0 sec and at least 19/20 correctly attributed, actually read source properties. A failure restores V3.10 files and restarts the pinned owner task; the V4 code is not merged to `main`.
- The test is scoped to browser-engine facts, not general current-events Web QA. Meeting it would NOT by itself prove the same latency/accuracy for arbitrary Web questions. Logged raw details stay on the owner PC; GitHub gets only aggregate totals and statuses.

Relevant primary-platform sources (independent public research, never injected into production answers): Firefox Gecko https://firefox-source-docs.mozilla.org/overview/gecko.html ; Firefox iOS WebKit https://firefox-source-docs.mozilla.org/overview/ios.html ; Tor mobile availability https://support.torproject.org/tor-browser/getting-started/installing/ ; Vivaldi desktop/iOS differences https://vivaldi.com/blog/ios/happy-3rd-birthday-vivaldi-on-ios/ .
